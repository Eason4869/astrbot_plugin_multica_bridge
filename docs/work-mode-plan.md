# Multica 工作模式实施与验收

用户已批准：保留现有插件与管理功能，`/multica` 进入、`/multica exit` 退出。
重点：旧 URL/Token 升级不丢失；工作模式其他插件与默认模型不回复。

## 设计约束

- 插件标识、plugin_data 数据目录、api_url/token 旧字段不变。
- 只合并新增默认项，初始化不写配置；写入前备份；损坏文件禁止默认值覆盖。
- 按平台实例、自身账号、群会话/私聊窗口隔离；同群所有成员共用模式和 Chat。
- 每条工作模式回复与提示统一前缀 `【来自 Multica｜工作模式】`。
- 绑定 Multica Chat，HTTP 提交和轮询；不使用 AstrBot 模型解析工作消息。
- 入口兼容层在命令过滤前接管；调用真实全局白名单/会话启停/限流/安全阶段。
- 工作模式故障保持接管；退出立即停止后续推送；停止远端任务是独立命令。
- 卸载撤销入口兼容层并取消本地 worker，不修改 AstrBot 源码。
- 旧管理指令及其权限保留；新增命令在指令管理注册。
- 首版文本完整支持；其他类型明确提示且不向其他插件放行。
- 后续用户授权重写并美化 WebUI：工作模式优先、会话列表、定向退出、连接与访问规则，浅色/暗色/移动端。

## 任务

1. 配置升级与保存：config.py、web_api.py；真实文件测试、Token 空白/脱敏/坏文件。
2. Chat HTTP：chat_client.py 复用旧客户端；本地 HTTP 服务验证路由/认证/响应/错误。
3. 会话存储与控制：session_store.py、work_mode.py；隔离/重载/进入退出/故障测试。
4. 入口与回传：astrbot_compat.py、reply_worker.py、main.py；真实上游消息阶段测试。
5. 设置页、双语、说明与版本；全量 pytest/Ruff、浏览器设置持久化验证。
6. 独立代码审阅，修复实质问题，生成可安装 ZIP 与验证报告；不自动发布远程。

## 验收

旧 0.9.0 配置升级、设置保存、重载后仍以同一 URL/Token 发送认证请求；配置备份可还原。
普通消息、其他插件合法/缺参数命令、等待会话、失败/不支持类型均无其他插件/模型回复。
进入/退出/新建/选择智能体/停止、跨聊天窗口隔离、重载与迟到回复抑制。
真实 QQ/Multica 环境若不可用，明确列为未验证，不把模拟测试写成线上验证。
